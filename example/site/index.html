GitHub template · human-in-the-loop AI development

You request. Your AI builds. Architecture keeps it honest.

archreator is a starting-point repository for making things with AI without losing the plot. You request changes and approve them; AI agents do the building in between. Every change is aligned through a small architecture ladder before a line of code is written — so moving fast never turns into a pile of confident nonsense.

Why bother with a process

Vibe coding is fast. Until it isn't.

Describing what you want and letting an AI build it is a genuine superpower. The failure mode isn't speed — it's drift: an agent confidently builds the wrong thing, three features quietly contradict each other, and nobody can say why any of it exists. The fix isn't slowing down. It's a lightweight ladder to climb before coding, and a human who says yes before anything ships.

Intent before code

Every change starts as a requirement checked against strategy — not a prompt that goes straight to a diff. The "why" is decided first, once.

A paper trail you can trust

Each architecture element names the file that realizes it. The docs stay checkable against the code, so they never quietly rot.

The human stays in charge

Agents can draft complete changes, but a person reviews and merges. Speed with a seatbelt, not autopilot into a wall.

The one rule

Climb five rungs before you code

A change in requirements is never coded directly. It's aligned top-down through five layers — each answering one question — recorded in a short scope document, and only then built. Same ladder for a human contributor and an AI agent.

1 Strategy & Motivation Why does this exist? Who cares? Does it hold up against the project's principles?
2 Business Who does what — which people and which AI agents — through which service and process?
3 Information What information exists, and how does it flow and persist?
4 Application Which software services and components realize the business services?
5 Technology What runtimes, hosting, and CI/CD does it all run on?

Assessed top-down — strategy first, technology last. A layer with nothing to change still gets an explicit "no change."

The payoff

When your Agent is an AI, this ladder is what turns "build me a thing" into a change you can actually review: the agent has to state the intent, the affected pieces, and the blast radius before touching code — so your review is a quick yes/no, not an archaeology dig.

Get going

From template to first change

Two clicks to your own copy, then point your AI coding agent at it and start describing what you want to build.

1

Use this template

On GitHub, hit Use this template → Create a new repository. You get a clean copy — the skills, the architecture skeleton, the PR templates — with its own history.

2

Fill in the intent

Replace the placeholders in CLAUDE.md and docs/ea/1_strategy/ with your project's real name, purpose, and principles. That's the top of the ladder.

3

Let your agent execute

Open it in Claude Code (or your agent of choice) and describe a change. The bundled skills make the agent climb the ladder, draft a scope doc, implement, and open a PR for you to review.
